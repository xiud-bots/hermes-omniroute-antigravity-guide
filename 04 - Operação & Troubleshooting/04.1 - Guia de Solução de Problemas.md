# 04.1 - Matriz de Resolução de Erros (Troubleshooting)

Diagnósticos rápidos e soluções de causa raiz para os problemas operacionais mais comuns.

---

## 🛑 1. `Connection Refused` em `127.0.0.1:20128`

**Sintoma:** O Hermes retorna erro `Cannot connect to host 127.0.0.1:20128` ou o cURL falha com `Failed to connect`.

**Causa Raiz:** O processo do OmniRoute não está ativo ou a porta foi alterada.

**Diagnóstico & Solução:**
```bash
# 1. Verificar se o serviço systemd está ativo
systemctl --user status omniroute.service

# 2. Se estiver parado ou com falha, reinicie:
systemctl --user restart omniroute.service

# 3. Inspecione os logs de inicialização
journalctl --user -u omniroute.service -n 50 --no-pager
```

---

## 🔑 2. Erro `401 Unauthorized` ou `Invalid API Key`

**Sintoma:** As requisições de chat falham com HTTP 401.

**Causa Raiz:** A chave em `~/.hermes/.env` está ausente, mal formatada ou foi revogada no OmniRoute.

**Solução:**
1. Abra o dashboard em `http://localhost:20128` e vá em **API Keys**.
2. Verifique se a chave em uso está com status **Active**.
3. Re-injete a chave no `.env`:
   ```bash
   echo "OPENAI_API_KEY=sk-sua-chave-aqui" > ~/.hermes/.env
   chmod 600 ~/.hermes/.env
   ```
4. No Hermes, recarregue as variáveis com `/reload`.

---

## 🔄 3. Erro de Conexão com Antigravity (`Token Expired` / `Auth Error`)

**Sintoma:** O OmniRoute retorna erro de provedor informando que as credenciais do Google expiraram ou foram revogadas.

**Causa Raiz:** A sessão OAuth 2.0 do Google atingiu o limite de vida ou houve troca de senha na conta Google.

**Solução:**
1. Acesse o painel do OmniRoute: `http://localhost:20128`.
2. Vá em **Connections** → encontre a conexão **Antigravity (`agy`)**.
3. Clique em **Re-authenticate (Reautenticar)**.
4. Complete o fluxo OAuth no navegador.
5. O status retornará para **Active** instantaneamente sem necessidade de reiniciar o Hermes.

---

## 🐳 4. Comandos de Sistema Falhando no Hermes (`systemctl: not found`)

**Sintoma:** O Hermes tenta rodar comandos de infraestrutura e falha dizendo que não encontra comandos do host.

**Causa Raiz:** O perfil do Hermes está configurado com `terminal.backend: docker` (container isolado) em vez de `terminal.backend: local`.

**Solução:**
```bash
# Alterar para execução local no host
hermes config set terminal.backend local

# Em perfis específicos (ex: forge ou potz)
hermes -p forge config set terminal.backend local
```
