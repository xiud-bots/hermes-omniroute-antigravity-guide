# 02.6 - Provisionamento do Serviço Systemd (`omniroute.service`)

Para garantir que o gateway OmniRoute esteja sempre disponível sem exigir que você abra um terminal manual e execute `omniroute`, provisionamos uma unit de serviço em escopo de usuário (`systemctl --user`).

---

## ⚙️ 1. Arquivo de Unit: `omniroute.service`

Crie o arquivo em `~/.config/systemd/user/omniroute.service`:

```ini
[Unit]
Description=OmniRoute AI Gateway & Proxy Service
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=%h

# Garante que o Node.js e executáveis em ~/.local/bin tenham prioridade
Environment="PATH=%h/.local/bin:/usr/local/bin:/usr/bin:/bin"
Environment="PORT=20128"
Environment="NODE_ENV=production"

# Executável do OmniRoute
ExecStart=%h/.local/bin/omniroute

Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal
LimitNOFILE=65536

[Install]
WantedBy=default.target
```

---

## 🚀 2. Comandos de Ativação

Você pode utilizar o script de setup fornecido no repositório:
```bash
./scripts/setup-omniroute-service.sh
```

Ou executar manualmente os comandos:

```bash
# 1. Garantir existência da pasta de units de usuário
mkdir -p ~/.config/systemd/user

# 2. Copiar a unit
cp systemd/omniroute.service ~/.config/systemd/user/

# 3. Recarregar o systemd
systemctl --user daemon-reload

# 4. Habilitar para o boot e iniciar imediatamente
systemctl --user enable --now omniroute.service
```

---

## 🔍 3. Verificação de Saúde e Logs

- **Checar status do daemon:**
  ```bash
  systemctl --user status omniroute.service
  ```
- **Acompanhar logs em tempo real:**
  ```bash
  journalctl --user -u omniroute.service -f
  ```

> [!TIP]
> **Dica para persistência contínua (Linger):**  
> Para garantir que o serviço continue rodando mesmo se você fechar a sessão SSH ou interface gráfica, habilite o linger:  
> `loginctl enable-linger $USER`

> **Está utilizando Windows?**
