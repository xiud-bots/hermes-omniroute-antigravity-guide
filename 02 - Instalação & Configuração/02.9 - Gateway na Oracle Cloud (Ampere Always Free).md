# 02.9 - Hermes Gateway Remoto na Oracle Cloud (Ampere Always Free)

Este guia avançado ensina como provisionar o **Hermes Agent como um Gateway 24/7** e o **OmniRoute** em uma máquina virtual gratuita na **Oracle Cloud Infrastructure (OCI)**, conectando-a com segurança ao seu **Hermes Desktop** local através de uma malha privada **Tailscale** e resolvendo o fluxo de login OAuth do Google Antigravity via **SSH Port Forwarding**.

---

## 💎 Vantagens Desta Configuração

1. **Recursos Robustos e Gratuitos:** A OCI oferece permanentemente até **4 OCPUs e 24 GB de memória RAM** na arquitetura Ampere A1 (ARM64), permitindo rodar múltiplos agentes, subagentes e cronjobs pesados em background 24 horas por dia.
2. **Zero Exposição Pública (Tailscale):** Não é necessário abrir nenhuma porta de rede no firewall público da Oracle Cloud. Toda a comunicação ocorre dentro da malha segura do Tailscale via WireGuard.
3. **Persistência de Longa Duração:** Se você desligar seu notebook ou perder a conexão Wi-Fi, as tarefas autônomas dos bots continuam sendo executadas no servidor da nuvem.

---

## 📦 Passo 1: Criando a Instância Ampere na OCI

1. Acesse o console da **Oracle Cloud** ([cloud.oracle.com](https://cloud.oracle.com)).
2. Navegue até **Compute** → **Instances** → **Create Instance**.
3. **Configuração da Imagem e Shape:**
   - **Image:** Selecione **Canonical Ubuntu 24.04** (ou Ubuntu 22.04) com arquitetura **aarch64 (ARM)**.
   - **Shape:** Clique em *Change Shape* → Selecione **Ampere (ARM Processor)** → `VM.Standard.A1.Flex`.
   - **Alocação Máxima do Always Free:**
     - **OCPUs:** `4`
     - **Memory (RAM):** `24 GB`
4. **Armazenamento (Boot Volume):**
   - Marque para especificar o tamanho do volume de boot com até `200 GB` (limite gratuito da OCI).
5. **Chaves SSH:**
   - Faça o upload da sua chave pública (`~/.ssh/id_rsa.pub` ou `id_ed25519.pub`).
6. Clique em **Create**. Aguarde a instância passar para o estado verde: **Running**.

## 🔒 Passo 2: Configuração da Rede Privada com Tailscale

Para evitar expor o Hermes e o OmniRoute à internet pública:

### 1. Na Instância Oracle (Conecte via SSH inicial):
```bash
ssh ubuntu@<IP_PUBLICO_DA_ORACLE>
```

Instale o Tailscale:
```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
```
- O terminal exibirá um link de login. Abra-o no navegador e autentique sua máquina na sua conta Tailscale.
- Anote o IP privado da VM gerado pelo Tailscale (exemplo: `100.85.120.45` ou hostname `hermes-oracle`).

### 2. No seu Computador Local (Windows / Linux / macOS):
- Certifique-se de que o Tailscale está instalado e conectado à mesma conta.
- Teste a conectividade direta:
  ```bash
  ping 100.85.120.45
  ```

> [!CHECK]
> A partir de agora, você pode conectar à sua VM diretamente pelo IP do Tailscale:  
> `ssh ubuntu@100.85.120.45` (ou `ssh ubuntu@hermes-oracle`).

## ⚡ Passo 3: Instalando Node.js, OmniRoute e Hermes no Ampere (ARM64)

Conectado via SSH na VM da Oracle:

```bash
# 1. Atualizar pacotes
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl git jq build-essential

# 2. Instalar Node.js 22 LTS (Binário Nativo ARM64)
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs

# 3. Instalar o OmniRoute globalmente
sudo npm install -g omniroute

# 4. Instalar o Hermes Agent
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
export PATH="$HOME/.local/bin:$PATH"

# 5. Habilitar linger para daemons persistirem sem SSH ativo
sudo loginctl enable-linger ubuntu
```

## 🔑 Passo 4: O "Truque" do SSH Tunnel para o OAuth do Antigravity

Como a VM da Oracle não possui interface gráfica nem navegador, como realizar o fluxo de login OAuth do Google Antigravity?

### A Solução: Túnel SSH com Encaminhamento de Porta Local

O OmniRoute escuta localmente em `http://127.0.0.1:20128`. Quando você inicia o OAuth, o Google redireciona a resposta com o código de autorização para `http://localhost:20128/auth/callback/...`.

Ao criar um túnel SSH encaminhando a porta local `20128` para a porta `20128` da VM remota, o seu navegador local entregará o callback diretamente para o OmniRoute na Oracle!

#### 1. Inicie o OmniRoute na VM Oracle:
```bash
# Na VM:
PORT=20128 omniroute
```

#### 2. No seu computador local (Windows ou Linux), abra o túnel:

**No Linux / macOS:**
```bash
# Usando o script pronto:
./scripts/tunnel-omniroute.sh ubuntu@100.85.120.45

# Ou via SSH nativo:
ssh -N -L 20128:127.0.0.1:20128 ubuntu@100.85.120.45
```

**No Windows (PowerShell):**
```powershell
# Usando o script PowerShell pronto:
.\scripts	unnel-omniroute.ps1 ubuntu@100.85.120.45

# Ou via SSH nativo:
ssh -N -L 20128:127.0.0.1:20128 ubuntu@100.85.120.45
```

#### 3. Realize o Login no seu Navegador:
1. Abra `http://localhost:20128` no navegador do seu notebook.
2. Defina a senha administrativa do OmniRoute e faça login.
3. Vá em **Connections** → **Add Connection** → Selecione **Antigravity (`agy`)**.
4. Clique em **Sign in with Google**:
   - Complete o login na sua conta Google.
   - O Google redirecionará para `http://localhost:20128/...`.
   - O túnel SSH intercepta a requisição e entrega o token à VM Oracle com sucesso!
5. Crie o Combo **`Antigravity-Smart`** e gere sua **API Key** (`sk-...`) conforme o passo a passo de [[02 - Instalação & Configuração/02.4 - Model Combo Antigravity-Smart|02.4]] e [[02 - Instalação & Configuração/02.5 - Chaves de API e Isolamento|02.5]].
6. Já pode fechar o túnel SSH no seu terminal local (`Ctrl + C`).

## ⚙️ Passo 5: Provisionando os Daemons Systemd na VM

Na VM da Oracle, configure o OmniRoute e o Hermes Gateway para rodarem 24/7 em background.

### 1. Daemon do OmniRoute (`~/.config/systemd/user/omniroute.service`):
```bash
mkdir -p ~/.config/systemd/user
cp ~/hermes-omniroute-antigravity-guide/systemd/omniroute.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now omniroute.service
```

### 2. Configurar o Hermes Agent na VM (`~/.hermes/config.yaml`):
```yaml
model:
  default: Antigravity-Smart
  provider: openai-api
  base_url: http://127.0.0.1:20128/v1
  api_mode: codex_responses

terminal:
  backend: local
  timeout: 180

gateway:
  # Escutar no IP privado do Tailscale para acesso pelo Hermes Desktop
  host: 0.0.0.0
  port: 8080
```

Insira a chave gerada:
```bash
echo "OPENAI_API_KEY=sk-sua-chave-do-omniroute" >> ~/.hermes/.env
chmod 600 ~/.hermes/.env
```

### 3. Daemon do Hermes Gateway (`~/.config/systemd/user/hermes-gateway.service`):
```bash
cp ~/hermes-omniroute-antigravity-guide/systemd/hermes-gateway.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now hermes-gateway.service
```

Valide os daemons:
```bash
systemctl --user status omniroute.service
systemctl --user status hermes-gateway.service
```

## 🖥️ Passo 6: Conectando o Hermes Desktop Local ao Gateway Remoto

Agora conectaremos seu aplicativo desktop local ao cérebro potente na nuvem Oracle:

1. Abra o **Hermes Desktop** no seu computador (Linux ou Windows).
2. Vá em **Settings (Configurações)** → **Gateway Connection**.
3. Altere o modo de conexão de *Local* para **Remote Gateway**.
4. No campo de endereço, insira a URL privada do Tailscale da VM:
   ```text
   http://100.85.120.45:8080
   ```
   *(ou `http://hermes-oracle:8080` caso o MagicDNS esteja ativo).*
5. **Pareamento Seguro:**
   - O Hermes Desktop solicitará o pareamento de dispositivo.
   - Na VM da Oracle (via SSH), liste e aprove a requisição:
     ```bash
     hermes pairing list
     hermes pairing approve <ID>
     ```
6. O status no seu Hermes Desktop ficará verde: **Connected (Conectado)**!
